## 评审使用指南

在线版公开访问，无需注册或填写密钥。建议使用桌面浏览器，按以下顺序体验，每次等待当前请求完成后再继续：

1. 点击“综合诊断”或输入“利润增长是否有现金流支撑”，查看本轮资料状态与解读。
2. 打开一条证据，核对原值、期间、单位、公式与原文；在“行情与新闻”查看本轮查询结果。
3. 在“问问证研”提问“现在股价多少”或“解释一下最近的走势”，点击引用继续核验。

### 预算、模型与连续提问

本项目以有限预算完成原型验证，模型选择和调用额度受当前 Groq 账户条件约束，尚未采购面向高并发评审的专用容量。当前使用 GPT-OSS 120B；分析型聊天遇到主模型限流时，会尝试同一 Groq 服务的 GPT-OSS 20B。备用模型同样受额度限制，不能保证绕过限流。

连续快速提问、较长上下文或多人同时体验，可能触发请求数或 token 额度限制，返回 HTTP 429。额度按服务商账户组织共享，并非每位访客独立；具体限额与恢复时间以账户配置和响应为准，参见 [Groq 限流说明](https://console.groq.com/docs/rate-limits)。建议单次提交并等待结果，出现限流时按页面倒计时再重试，避免反复点击。若每日额度已耗尽，需要等待额度重置或由维护者调整服务配置。

### 网络访问与失败兜底

若网页本身无法打开，可尝试切换网络；在所在地及所在机构规则允许的情况下，也可尝试 VPN 或代理。**VPN 不是使用前提，也不能解决服务端模型额度、接口鉴权或服务端连接故障。** 当前没有完成各地区网络环境的普遍可达性验证。

| 遇到的情况 | 当前产品处理 | 建议操作 |
| --- | --- | --- |
| 聊天提示模型限流 | 有界重试并尝试备用模型；仍失败则保留问题并显示等待提示 | 按倒计时重试一次；持续失败时暂停 AI 提问，先查看证据。每日额度以服务商重置时间为准 |
| 模型超时或连接失败 | 综合诊断保留证据并标明规则模式；分析型聊天保留问题和重试入口 | 稍后重试。规则整理不代表本次 AI 调用成功 |
| 行情或新闻查询失败 | 显示缺失、权限、超时或限流等具体状态，不填造价格，不把失败写成“没有新闻” | 刷新对应资料面板；仍失败时按缺口理解结果，继续查看已加载资料与财报证据 |
| 回答无法对应来源 | 尝试一次格式修复；仍无法验证则保留问题并提示失败 | 可通过证据抽屉核查原始字段，或聚焦一个指标追问；此类失败不能一概归因于额度 |
| 页面无法加载 | 浏览器无法正常取得页面，尚未进入模型问答环节 | 检查网络、换网络后重新打开；必要时按上述条件尝试代理 |

“AI 解读”对应真实模型调用；“行情查询”由接口字段直接生成，独立于模型额度，但仍依赖行情服务；“规则模式”是明确标记的降级结果。模型暂不可用时，已加载的财报证据、确定性计算与研究记录导出仍可使用。

以上说明是演示环境的使用边界。已完成的实际调用与异常测试分别见 [验证记录](docs/VERIFICATION.json) 和 [测试说明](docs/TESTING.md)，不将一次成功等同于持续可用。

## 产品选择与目标用户

选择“个股多维诊断与证据验证”，将范围限定为一家 A 股公司。面向希望复核公司经营状态的个人研究者，优先完成“问题 → 诊断 → 证据 → 原文 → 追问”的主链路。

例如输入“利润增长是否有现金流支撑”，同时检查利润、经营现金流、存货、应收账款与合同负债。综合诊断还会纳入本轮取得的价格、估值、历史走势和媒体线索，区分支持信号、负面信号、矛盾与未知，不输出一个笼统的投资评分。

## 核心体验

1. 输入研究问题，或选择综合诊断、增长质量、业务结构、风险与反证。页面自动定位到结果区，显示等待状态并原位更新。
2. 在“诊断概览”查看本轮资料状态、AI 解读和相关证据；目录顺序为诊断、行情与新闻、证据、数据与方法。
3. 打开证据抽屉，核对原值、单位、报告期或行情区间、来源链接、计算公式和推断边界。
4. 在“行情与新闻”查看前复权收盘折线、区间涨跌幅、收盘价最大回撤、估值倍数和新闻片段。
5. 通过“问问证研”连续追问公司、指标、行情或新闻问题；引用可以回到对应资料。
6. 搜索和筛选证据、保存本浏览器核验标记，导出 Markdown 研究记录或 JSON 原始字段。动态证据按本轮版本保存，避免刷新后新闻编号指向别的内容。

## 本地启动

推荐 Node.js 24 与 npm。最低要求 Node.js 22.13；测试使用 Node.js 24。

```bash
git clone https://github.com/Hanzhi322/ai-stock-diagnosis-submission.git
cd ai-stock-diagnosis-submission
npm ci
cp .env.example .env.local
# 在 .env.local 填写自己的服务端密钥
npm run dev
```

打开终端给出的地址，默认 `http://localhost:5173/`。

```bash
npm test
npm run typecheck
npm run build
npm start
```

`npm start` 运行已构建的本地 Worker；地址以命令输出为准。无需数据库。生产环境同样需要单独配置服务端变量，不能仅依赖本机 `.env.local`。

## 环境变量

| 变量 | 用途 |
| --- | --- |
| `LLM_API_KEY` | Groq API Key，仅服务端使用 |
| `LLM_BASE_URL` | 默认 `https://api.groq.com/openai/v1` |
| `LLM_MODEL` | 当前验证模型 `openai/gpt-oss-120b`（由 Groq 托管） |
| `ENABLE_CHAT_PREVIEW` | 设置为 `true` 启用对话、行情、新闻与综合诊断；保留此名称以兼容早期配置 |
| `FUYAO_API_KEY` | 扶摇金融数据 API Key，查询价格、日线与估值 |
| `IFIND_API_KEY` | iFinD MCP 新闻服务的 Authorization 值，按服务商配置原样填写 |
| `IFIND_TRANSPORT` | 生产已验证 `direct-tls`；使用校验证书的 TLS 连接官方端口。留空走标准 fetch |

三家凭证互不通用。只填 Authorization 值，不把整段 MCP JSON 放入环境变量。不要使用 `NEXT_PUBLIC_` 前缀，不要将真实密钥提交到仓库、聊天或前端表单。`.env.local` 已被 Git 忽略；`.env.example` 仅提供空密钥示例。

缺少金融数据权限时显示具体资料缺口。缺少模型密钥或模型调用失败时，诊断明确显示规则模式；分析型聊天明确显示失败或重试提示；直接行情查询不依赖模型配置或额度，标注为接口数据，不冒充 AI 成功。公开演示站的凭证由服务端配置，访问者不需要填写密钥。

## 数据来源与口径

| 来源 | 实际用途 | 时点与边界 |
| --- | --- | --- |
| [巨潮资讯半年报](https://static.cninfo.com.cn/finalpage/2026-07-24/1225442062.PDF) | 固定财务快照、业务结构、行业份额转引和分红方案 | 报告期 2026-01-01 至 2026-06-30，披露 2026-07-24，半年度报告未经审计 |
| [同花顺扶摇](https://fuyao.aicubes.cn/docs/) | 报价快照、前复权日线、PE TTM/MRQ、PB MRQ、PS TTM、PCF TTM | 查询近 90 个自然日，最多保留末 60 根有效日线；行情与估值时间独立 |
| [iFinD MCP](https://mcp.51ifind.com/) | 最近七个自然日、最多五条公司相关新闻片段 | 保留标题、发布时间、检索范围、抓取时间、URL 与核验提示；片段未等同于完整原文 |
| [宁德时代官网](https://www.catl.com/) | 对话中的公司业务介绍 | 概念与公司介绍不等同于实时财务结论 |
| [Groq](https://console.groq.com/docs/overview) | 对已取得资料进行语言解释 | 模型服务，不是金融数据源；未接入 Yahoo Finance |

财报金额原始单位为人民币千元，展示亿元时除以 100,000。财务流量同比使用 2025 H1；存货、应收与合同负债比较 2025 年末。现金流为合并口径、净利润为归母口径，该比值不等同于严格的利润现金转化率。行业份额为报告转引 SNE Research，统计期间为 2026 年 1—5 月，未独立复核其底层数据库。PDF 链接处理了封面导致的一页偏移。

行情与估值上游 timestamp 是数据就绪时点，不能当作最近成交时间或具体估值交易日。区间涨跌幅从所返首日收盘算到末日收盘；最大回撤只使用日收盘价。媒体发布时间不一定是事件发生时间，不把新闻与股价变化直接判为因果。

## AI、计算与接口如何分工

- **确定性计算**：代码计算同比、毛利率、比值、区间涨跌幅和回撤；缺失值不补零，非正分母不按正常指标处理。
- **证据获取**：后端调用扶摇 REST 和 iFinD Streamable HTTP MCP；MCP 包含初始化、工具发现与 `search_news` 调用。密钥不进入浏览器。
- **综合诊断**：首次打开收集资料并进行规则整理；点击诊断才调用 Groq。模型负责选择证据和解释关系，诊断正文只写定性关系，数字在证据卡中确定性展示。
- **聊天**：直接查股价、涨跌幅、成交量等由接口字段生成回答，展示来源与时点。分析问题调用模型，将金融数字绑定已知字段；允许指标、数值、单位和出处都匹配的直接复述。推荐追问统一用户口吻，单独处理，不因建议格式不合适而拒绝正文。新闻数量只能按对应片段的准确单位转述，冲突片段的争议数字不用于推论。
- **失败处理**：鉴权失败、超时、限流、数据格式异常、输出校验失败分别保留状态。短时缓存与请求合并减少重复查询；重试有次数和时间上限。聊天主模型 GPT-OSS 120B 限流时，会切换同一 Groq 服务的 GPT-OSS 20B，使用相同证据与校验；返回字段 `model` 记录实际使用的模型。

当前数据选择由后端规则组织，未实现模型自主规划任意工具链。校验可阻止部分无依据数字、未知引用和交易语句，但不能保证所有解释语义正确；用户仍需要核对原文。

## 已知边界与未做事项

- 仅支持宁德时代；财务字段为公开报告快照，并非自动更新的完整财务数据库。
- 已取得的价格和估值不能替代同行比较、历史估值分位及底层盈利/股本核验。
- 新闻只覆盖检索窗口和返回片段，未自动逐篇阅读原文；冲突检测只覆盖已实现的明确模式，不保证发现所有矛盾。
- 不提供确定性涨跌预测、收益承诺、买卖点、交易执行或个性化持仓建议。
- 无回测、自动事件监控、跨设备同步或生产级多租户配额系统。核验标记存于本浏览器，研究历史为当前会话状态。
- 模型与数据服务受权限、额度、限流和网络影响，成功验证不表示永久或无限并发可用。
