# 证研 · 个股证据工作台

**项目总用时：3h**

一个围绕宁德时代（300750.SZ）的研究工具：从问题选择诊断维度，再沿结论回到原始财报字段、计算公式和验证边界。

**当前版本使用公开公告快照与 Groq 在线模型，已完成线上真实请求验证。未配置密钥或模型调用失败时，界面明确显示规则降级。**

在线体验：[证研](https://zhengyan-evidence-workbench.zuhanzhizzz.chatgpt.site) · 源码：[Hanzhi322/ai-stock-diagnosis-submission](https://github.com/Hanzhi322/ai-stock-diagnosis-submission)。

## 目标用户与核心任务

面向希望复核公司经营状态的个人研究者。输入“利润增长是否有现金流支撑”，得到现金流、归母利润、营运资本的交叉证据；点开证据可以看到报告页码、原值、单位、期间、公式、推断与待验证问题。

## 产品经理与 AI 的协作示例

以下为结合本项目背景创作的协作情境示例，围绕三小时交付目标展开。实际执行与测试结果见 [AI 使用与验证记录](docs/AI_USAGE.md) 和 [测试说明](docs/TESTING.md)。

### 刚开始，先把题选下来

**我：**我们只有三个小时，先别写一大份方案。你把这三道题看一下，哪个最有可能做出一个真的能用的东西？我比较担心最后只剩一个漂亮页面，点进去什么都没有。

**AI：**个股诊断可以先限定一家公司，用公开财报把问题、指标和证据串起来。选股需要股票池，事件时间线需要持续演化的材料，数据准备会更重。

**我：**那就个股。公司也先别做多选了，先把一家做完整。不过我不想打开以后就是一段很长的 AI 分析。比如我问“利润增长有没有现金流支撑”，至少得让我知道它凭什么这么说。

**AI：**可以在解释下面放相关证据，展开后看原始字段、公式和来源。

**我：**可以，先按这个做。你遇到可能卡住交付的依赖早点告诉我，尤其是数据和模型接口。

### 开始做以后，先把数据问题问清楚

**我：**你先拿核心字段做一次最小查询，看看扶摇和 iFinD 的权限、返回字段和报告期能不能满足要求。别只确认接口返回成功，我们用到的比较期和单位也要齐。缺哪些字段直接列出来，先判断会卡住哪些结论。

**AI：**如果没有可用权限，可以先用公开财报整理一个固定快照，但实时行情和估值就不能完整提供。

**我：**那先用能核对的财报。页面上把日期写清楚，哪些没接到也直接写。用户问“现在贵不贵”的时候，不能因为已经有利润数据，就顺着给一个估值结论。

**AI：**估值相关的问题会展示缺失数据和待验证项。

**我：**行，但“无法判断”后面最好告诉他缺什么。只有一句不知道，用户还是接不下去。先做到这一步，实时数据别在这三个小时里硬加。

### 看第一版时，先顺着用户的问题走一遍

**我：**我先按一个普通用户的方式试一下，不看你介绍。打开以后能不能给我几个问题入口？不是所有人都知道要怎么问。

**AI：**可以提供增长质量、业务结构和风险这几个切入点。

**我：**可以。我先点增长质量。现在这些指标都有了，但我还得自己找哪两个值得一起看。能不能让结果更贴着我刚才的问题？我问现金流，就先让我看到现金流和利润的关系。

**AI：**可以根据问题调整证据顺序，把相关信息放在前面。

**我：**对。还有，别因为要回答我的问题，就只留支持结论的材料。方向不一致的东西也要在，不然看起来很顺，实际上没帮我研究。

### 点开证据，再追问一句

**我：**这个证据点开以后，不要只是把我扔到一份几十页的 PDF。我现在想核对的是哪个数、哪一期，能不能先在这里看到？

**AI：**详情里可以放原始值、比较期、单位和计算公式，再提供原文页码链接。

**我：**这样比较有用。还有一个口径问题：利润是同比，存货是不是拿期末跟年初比？这两个别都写成“增长”。用户可能会以为是在比同一段时间。

**AI：**可以明确区分同比和较年初变化，并在字段旁保留比较期。

**我：**好。这种小地方比再加一个图重要，先把它对上。

### 模型接上了，也要看看它到底在做什么

**我：**财务计算先固定在代码里，模型只负责选证据和解释关系。重点看一下现金流和归母利润的口径差异：比值算对了，也不能直接把它解释成严格的利润现金转化率。

**AI：**可以在证据详情里保留口径说明，同时把这一限制传给模型，并检查解释是否越界。

**我：**对。正文里的数字也别让模型重新生成，直接引用确定性结果。另外，检查是不是每个被引用的证据编号都能打开，别出现解释提到了依据、页面却找不到的情况。

**AI：**可以限制输出范围，并检查返回的证据编号和结构。

**我：**检查还是要有，但结构正确也不代表它说得对。你再看一下它会不会把“可能是回款变慢”直接写成“回款变慢导致现金流下降”。没有证据的原因，要给它留在可能性上。

### 出现降级时，先弄清是哪一步有问题

**我：**这次落到了规则结果，先看下是哪一层触发的：上游状态码、返回结构，还是我们的输出检查？别先去改提示词，把失败原因定位出来。

**AI：**可以分别检查上游请求与本地校验，并保留具体失败原因。

**我：**如果是校验拦截，把被拒绝的输出拿出来看一下，确认是不是误伤了合法的证据编号。如果是限流，再看重试等待值不值得。我们时间有限，先修导致正常问题也无法完成的那一项。

**AI：**可以分别记录失败原因，再对对应问题修正。

**我：**嗯。还有失败的时候，已有证据别一起消失。用户至少还能继续看财报。页面要说清楚这次没生成新的 AI 解读，不要让我猜现在看到的是哪一种结果。

### 本地跑通以后，我还要看线上

**我：**你等会儿把本地和线上分开测一下。同一个问题各跑一次，给我看实际结果。只说“模型已配置”，我还是不知道评审点开以后能不能用。

**AI：**可以分别验证真实调用和返回模式，并检查公开访问。

**我：**还有源码和链接。评审拿到的应该是我自己的项目，网页、仓库和压缩包要对得上。不要我发过去以后，他还需要找我要账号或者猜怎么启动。

**AI：**发布后会检查访问权限，并同步源码与提交说明。

**我：**行。先把这些确认好，新功能先停一下。

### 最后才改 UI，而且这轮范围很小

**我：**现在这样基本可以了。我想把颜色改得科技一点，蓝紫渐变可以试试。不过其他别动了，我们没时间重新验一遍整个产品。不好看我可能还要换回来。

**AI：**先保存原配色，只修改颜色，给你本地预览。

**我：**对，先别直接更新线上。正文还是要好读，风险和未知那些状态别都变成同一种紫色。

**AI：**会保留状态区分，并检查手机和电脑上的效果。

**我：**这个可以，就用这版。更新线上以后再点一次诊断，确认不是只换好了样式，功能出了问题。

### 准备提交时，再确认能力边界

**我：**最后核对一次交付说明。数据来源按代码里的实际调用写，金融数据接口、公开资料和模型服务分别列，文档里提过但没接入的不要算已完成。线上版本、源码和说明里的能力范围也要一致。

**AI：**当前使用公开财报快照和 Groq 模型，没有接入这些金融数据接口。

**我：**好，明确写财报快照的时点和未覆盖项。演示就用已经验证过的现金流问题，从诊断走到反证，再打开原始字段和来源。把这条路径演示完整。

**AI：**可以按提问、查看矛盾证据、打开字段与来源的顺序演示。

**我：**好，最后把链接、源码、启动说明和测试记录放在一起。我自己再完整走一遍。

## 本地启动

Node.js 22.13+（测试使用 Node.js 24）与 npm。

```bash
git clone https://github.com/Hanzhi322/ai-stock-diagnosis-submission.git
cd ai-stock-diagnosis-submission
npm ci
cp .env.example .env.local
npm run dev
```

打开启动日志中的 Local URL（默认 http://localhost:5173）。

## 模型配置

仅修改服务端 `.env.local`，不在浏览器输入、不提交密钥。

```dotenv
LLM_API_KEY=你的密钥
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=qwen/qwen3.8-27b
```

兼容 `/chat/completions` 协议；其他供应商请填写自己的 HTTPS base URL 与模型名，是否支持 `response_format: json_object` 以服务商文档为准。参考 [Groq 官方接入文档](https://console.groq.com/docs/overview)。

线上环境需要另外配置相同的服务端变量。应用不会把本机密钥打包进源码或部署包。仅凭 `.env.local` 不会自动配置线上环境。调用费用由模型服务商收取。

`GET /api/status` 仅返回是否配置与模型名称；`POST /api/diagnose` 接收 `{ "question": "..." }`。问题限 500 字，上游调用共享 20 秒超时；429 按服务端 Retry-After 至多重试两次，过长等待或持续限流明确显示原因。未配置 / 超时 / 上游错误 / 输出校验失败均明确降级。Key 已配置并不等于服务实际可用，需成功调用验证。

## AI、计算与数据的分工

- 数据：冻结公开财报快照，人工式字段抽取由 AI 辅助、原始页面核对；不动态编造财务数字。
- 确定性引擎：金额换算、同比、毛利率和现金流比值。缺失值与非正基数不按正常值计算。
- 规则基线：关键词选取有限维度，提供可操作的降级路径；无法理解任意自然语言。
- LLM：根据公司类型与问题重排证据、解释关联；模型正文不得生成财务数字、来源或交易指令；已有 E01—E07 证据编号按白名单校验。仅接受已有证据编号，自动保留规则路径中的反证/未知项。
- 输出校验是有限的结构与文本检查，不能保证语义完全正确；界面保留人工复核入口。

## 数据来源与口径

唯一基础财报：[宁德时代 2026 年半年度报告，巨潮资讯](https://static.cninfo.com.cn/finalpage/2026-07-24/1225442062.PDF)。

- 报告期：2026-01-01 至 2026-06-30。
- 披露：2026-07-24；本项目核验：2026-09-26。
- 财务报表未经审计；快照版本 `catl-2026h1-v1`。
- 原始金额单位：人民币千元；显示亿元时除以 100,000。
- 财务流量同比：2025 H1；应收、存货、合同负债：2025 年末。
- 现金流/归母净利润存在合并口径与归母口径的差异，不当作标准现金转化率。
- 市占率是财报转引 SNE Research，期间为 2026 年 1—5 月，未独立核验第三方数据库。
- 半年报印刷页码比 PDF 浏览器页序小 1；链接已处理偏移。
- 扶摇文档访问未成功，且当前未获得扶摇/iFinD 调用权限。故使用公开公告并明确来源，不声称已经接入。

原始字段与计算在 `lib/research.ts`，可以从网页“数据与方法”下载 JSON。

## 已知边界与未做事项

- 只支持宁德时代，不支持任意股票输入。
- 估值、实时行情、历史复权 K 线、同行可比估值尚未接入，显示未知。
- 未核验公告披露之后所有事件；分红方案不等同于已实施。
- 不提供涨跌预测、收益承诺、买卖点或交易指令。
- 没有自动抓取、回测、持仓、交易或跨设备收藏。核验标记只保存在本浏览器。
- 已使用 Groq 完成真实模型请求验证。无 Key、上游异常或输出不合格时仍显示规则降级，验证记录见测试说明。
- 无互联网的财报快照仍可研究；在线模型需要网络与可用余额。
- 尚无生产级多租户配额、持久化速率限制或全量监控。当前演示站已按所有者要求公开，模型账户额度由服务商管理；正式规模化运行前需要补充持久化用量控制。

## 技术与结构

React / TypeScript / Vinext（Next.js 风格路由）/ Cloudflare Worker / Tailwind / Shadcn / Lucide。前端组件 `app/page.tsx`；诊断端点 `app/api/diagnose/route.ts`；纯计算与证据层 `lib/research.ts`。

应用围绕问题诊断、确定性指标计算和证据核验组织。各依赖包保留其许可证。

提交清单见 `docs/SUBMISSION.md`；AI 使用记录见 `docs/AI_USAGE.md`；演示顺序见 `docs/DEMO.md`。浏览器支持 WebMCP 时注册打开证据与执行诊断两个工具，直接调用相同的可见状态与动作。
