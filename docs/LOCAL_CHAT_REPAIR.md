# 对话与检索修复 · 本地验证记录

日期：2026-09-26（纽约时间）。分支：`fix/chat-retrieval-local`。

本记录针对本地候选修复版本。未部署线上、未推送 GitHub、未替换既有评审材料或 ZIP。生产环境的行为不能由本记录推定。

## 已定位的问题

- 原先 iFinD 只调用新闻端点；财务、公司信息及公告未进入按问题检索链路。
- “现在还缺哪些关键信息？”未匹配原先的财务关键词，模型看不到完整的已有财报证据。
- 模型输出字面 `\\n`、括号列表编号、不同日期格式或缺少可补全的引用元数据时，原校验会把整条回答拒绝。
- 模型把多句写在一段时，一句无依据数字会连带吞掉其他有依据的内容。
- 较早轮次的模型回答可能干扰最新行情追问。历史回答本身不能充当新一轮的事实来源。

## 本地改动

1. 使用既有 `IFIND_API_KEY` 连接综合 MCP 端点，并发现、调用 `get_stock_summary`、`get_security_indicators`、`search_notice`、`search_news`。行情、日线、估值继续使用扶摇。
2. 根据问题选取最多两类查询；模型可提出一次针对性补查。设置超时、缓存及并发合并。检索失败不清空已经取得的财报、行情等证据。
3. 按句保留有效内容，保持原段落结构。无法确认的句子和依赖它的后续结论一并暂缓；列表、换行及可核对的日期格式自动整理。问题不是通过“允许任何数字”来解决的。
4. JSON 格式错误中的模型正文仍进入同样的检查流程。需要重写时传递具体问题；不向用户展示内部校验或修复过程。不把确定性资料整理冒充模型回答。
5. 连续对话向模型保留紧邻一轮交互，并按最近问题重新取得资料。更早回答不作为当前数据源。
6. 数字保留来源、单位和时点。接口仅标注 MRQ 时不猜测具体报告期；实际日期优先。未来期次、同期间数量级冲突、识别失败和空结果不视为正常最新财务数据。同比增减额不能写成当期总额。

## 实际调用观察

- 原截图问题已在本地网页得到真实模型回答，并显示可点击的 E01、E02 等证据。
- 查股价由扶摇实际接口直接返回，并显示快照时点；不依赖 Groq 额度。
- 连续“股价 → 最近走势”在修复后的本地接口取得真实 Groq 回答，引用 H01、M01；新闻追问也实际调用 `search_news` 并引用 N 类来源。
- 公司概况查询采用已验证能识别主体的简短查询“宁德时代主营业务”。复杂拼接证券名称与代码的查询曾返回“未能识别”，不能把这种文本算成公司信息。
- 公告检索曾返回现金流变化说明，也曾为空；指标查询曾返回旧日期及晚于查询日的日期。这些都是需要处理的上游情况，不能承诺每次检索一定有结果。
- 测试中确实发生 Groq 120B 限流，20B 备用模型接续成功；20B 也可能独立限流。限流与内容检查是不同原因，产品保留限流状态及重试等待提示。
