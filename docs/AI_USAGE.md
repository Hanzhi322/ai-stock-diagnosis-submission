# AI 使用与验证记录

## 工具与分工

开发过程中使用 Codex 辅助范围分析、公开资料整理、前后端实现、接口适配、测试、错误排查和文档整理。产品运行时使用 Groq 托管的 `openai/gpt-oss-120b` 进行诊断与对话解释，开发初期使用过 `qwen/qwen3.8-27b`；扶摇和 iFinD 提供金融数据与新闻，不承担模型角色。

候选人负责提出目标、配置可用服务、体验反馈和发布决策；Codex 执行实现与技术检查。下文按实际反馈与修正归纳，不将自动测试描述为候选人逐项手工完成，也不将整理后的叙述当作逐字聊天实录。

## 从可用主链路到多来源研究

项目启动时以三小时作为初版交付目标，先限定一家 A 股公司，完成提问、诊断、证据抽屉与原文核验。后续按实际体验增加对话、行情、估值、历史日线与新闻，并继续修正交互。

| 候选人的产品判断或反馈 | 本次落实的变化 | 验证关注点 |
| --- | --- | --- |
| 尽快做出能交付、能实际操作的产品 | 选择个股诊断，聚焦宁德时代，优先完成一条研究主链路 | 问题能够得到结果，结论能够打开证据 |
| 本地模型成功不代表线上成功 | 分开检查本地与公开版真实 Groq 请求 | 返回模式、上游错误和降级原因，不仅看“已配置” |
| 页面需要独立的对话入口 | 增加公司问答、推荐问题、追问与引用，并在首次发送前主动说明可问内容 | 公司介绍、数值引用、缺口回答和会话连续性 |
| 已提供数据接口，应把行情和新闻用于研究 | 接入扶摇与 iFinD，并在页面显示来源与时点 | 检查实际工具返回、授权、异常和单位 |
| “诊断概览像财报解读，应该结合新查询的数据” | 将价格、估值、走势和新闻纳入诊断目录，按取数结果更新缺口 | 模型输入包含本轮动态证据；失败数据不包装成正常结果 |
| 内容切换了，但用户仍停留在页面上方 | 目录切换滚动到对应区域；开始诊断与快捷问题滚动到结果区 | 等待状态、完成后原位更新、重复点击与空输入 |

| 评审连续追问可能限流，应说明预算限制与失败后的使用方式 | 在 README 增加评审指南，区分网页网络、模型额度、金融数据接口和输出校验问题，并说明各自兜底 | 按当前代码和服务商文档核对说明，不把所有失败归因于额度，也不把 VPN 写成必需条件 |

## 实际发现并修正的问题

1. **计算与口径**：比值差先用未四舍五入原值计算，再展示；区分同比与较年初变化；明确合并现金流和归母利润的口径差异；财报页码处理封面偏移；行业份额注明转引与期间。
2. **数字校验误伤**：合法证据编号及已知报告日期曾被当成未经证实的数字，导致正常问题失败。改为只豁免白名单编号和确切已知字段，未知编号及无依据金融数字仍拒绝。
3. **新闻数值转述**：保留原片段的单位和引用要求；准确匹配且没有冲突的数量才允许转述。相同片段出现不同动力电池收入数值时标为冲突，不择一编成结论。
4. **模型限流与失败分类**：实际出现 Groq HTTP 429。复核上游错误后，发现初期 Qwen 模型的每日额度接近耗尽，切换到同一 Groq 账户下验证可用的 GPT-OSS 120B，并适配低推理强度与输出上限。新闻定性问题不再附带无关数值表，实测提示输入从约四千九百 token 降到约三千三百 token；数值问题仍保留对应字段。尊重 Retry-After 并限制重试，不把规则降级称为 AI 成功。
5. **MCP 接入**：按照实际工具清单适配初始化、`search_news` 参数和双层 JSON 返回；鉴权值保存在服务端。修正 Worker 不支持的重定向选项，避免把调用失败误读成“没有新闻”。
6. **动态证据一致性**：原概览只引用固定财报。现将本轮多来源资料送入模型，并保留未取得的数据；导出与历史诊断绑定当轮目录，核验标记随动态资料版本变化。
7. **结果可见性**：仅切换标签不足以让用户看见结果。增加目录定位、结果区定位、等待提示和失败重试入口；空问题仍回到输入框，不误跳到旧结果。
8. **生产与本地差异**：iFinD 初始化曾在线上超时。候选人要求新闻必须实际可用；通过阶段日志和本地对照定位到传输环节，改用证书校验开启的服务端 TLS 直连，并适配 Worker 不支持的 ALPN 选项。生产端实际返回五条新闻后才记为修复；补充八项传输解析及异常测试。

9. **回答可用性与用户口吻**：候选人反馈“问股价反复失败”“推荐问句应是用户下一轮发言”。按截图复现“问候 → 查股价”后，确认模型与行情均成功，但行情已证明的股票代码被错误要求额外引用公司介绍。修正该引用关系；直接查价改为接口字段回答。合法数值按指标、单位和出处核对；建议问句独立规范为用户口吻，不拖累正文。常见概念不再携带完整财报，主模型限流时使用已验证的同服务商备用模型；数值缺失和真正的上游故障仍如实展示。

## 如何验证 AI 输出

财务数字与公式由代码计算；模型返回校验结构、引用编号、数字来源与边界语句。自动测试模拟无依据数字、错误单位、缺失字段、接口失败、限流和交易请求；真实请求与浏览器检查再确认模型实际工作、抽屉可追溯及交互可见。

这些检查不能证明所有分析语义正确，新闻片段也不是已独立核实的事实。候选人可依据来源链接继续复核；发布和真实请求结果见 [TESTING.md](TESTING.md) 与 [VERIFICATION.json](VERIFICATION.json)。评审遇到限流或网络问题时，可参考 [README 评审使用指南](../README.md#评审使用指南)。
