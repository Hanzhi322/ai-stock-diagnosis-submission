# AI 使用与验证记录

## 如实披露

本项目由候选人与 Codex 协作完成。Codex 参与选题范围分析、产品方案、公开资料查找、字段抽取、前后端实现、测试编写、异常诊断及文档整理。候选人提供题目与时间限制，并决定采用个股诊断题。

不声称候选人逐行手写全部代码，也不将 AI 自检写成候选人亲自完成的核验。

## 产品中的 AI 角色

未配置 Key：确定性计算 + 有限关键词路由 + 预先编写的证据解释，页面标注“规则模式”。
配置 Key 后：在线模型根据问题和制造业公司属性选择相关证据、解释不同证据的关系；模型不得生成金融数字。数字统一由确定性层提供；来源和字段来自冻结数据集。真实模型调用是否完成以 `docs/TESTING.md` 的记录为准。

## 实际修正的错误与不合理结果

1. 首版界面曾按展示后的比值计算变化，给出 −0.54 倍。改为先对未四舍五入的原始值计算差，再统一展示，结果 −0.53 倍。
2. 区分财务流量同比与资产负债表期末对年初，避免将存货、应收的“较年初变化”标成同比。
3. 现金流分子为合并口径、利润分母为归母口径，因此将指标明确命名为“现金流 / 归母净利润”，并展示少数股东口径边界。
4. 行业份额注明公司转引第三方、统计期间为 1—5 月，不将其当成独立核验的 1—6 月完整同行比较。
5. 分红标记为披露方案，未核验后续实施公告，不把拟分红写成已实施。
6. 源 PDF 有封面偏移：报告印刷页 7 的链接使用 PDF 第 8 页。
7. 修正前端响应的 TypeScript unknown 类型问题，完成类型检查。
8. 模型上游错误和不合格 JSON 一律降级并显示原因，不展示虚假的 AI 成功状态。

9. 真实 Groq 调用时，模型在正文重复证据编号和数字列表导致校验拒绝；调整提示为自然段和独立编号数组，再验证真实模型成功。
10. 服务商账户实际可用模型与默认示例不同，通过模型列表与实际请求确认后使用 Qwen。

11. 再次实测发现证据编号被数字校验误伤，改为只豁免已存在的证据编号；未知编号及财务数字仍被拒绝。
12. 生产日志确认部分降级来自 Groq HTTP 429，压缩重复提示、缩短输出，并遵循 Retry-After 做有界重试；持续限流显示独立原因。

## 验证方式

- 用巨潮资讯报告中的财务表核对原值、单位、期间和页码。
- 使用独立预期数字检查同比与毛利率。
- 通过缺失、零分母、负分母、非有限数等输入测试计算边界。
- 模拟模型生成不存在的证据、未核实数字、交易建议及接口异常，验证降级。
- 浏览器实际操作问题诊断、证据抽屉、搜索/筛选与工具调用。
